# SAQTA API contract

Base URL `http://localhost:8000/api`. All prices are integer KZT; all quantities integer units; weights grams. Dates ISO `YYYY-MM-DD`; datetimes ISO UTC. Errors `{detail: string | validation issues, errors?: [{row,message}]}`. No authentication; isolated demo only. Lists return arrays except records (paginated object). `location_id`, `start_date`, `end_date` optional on analytics/inventory/records. Date filters inclusive. `WORKSPACE_MODE=demo|real` controls seed/reset authorization; source origin is also persisted in `ApplicationSettings.workspace_mode`, so changing an environment variable cannot relabel synthetic records as real. Use a separate database and `python -m app.seed --empty` for an empty real-data workspace. No implicit seed on startup.

- GET `/health`: `{status:"ok",service:"SAQTA",database:"connected",workspace_mode:"demo",demo_data:true}`
- GET `/locations`: `[{id,bakery_id,name,address,city}]`
- GET `/products`: `[{id,name,category,unit,price_kzt,cost_kzt,weight_grams,is_active}]`; POST same editable fields without id; PATCH `/products/{id}` partial same.
- GET `/bakery`: `{id,name,city}`; PATCH `{name,city}`.
- GET `/settings`: `{bakery_name,city,currency:"KZT",safety_buffer_percent:10,workspace_mode,demo_data,data_source,auth_enabled:false}`; PATCH `{bakery_name?,city?,safety_buffer_percent?}`.
- GET `/inventory`: `[{id,product_id,product_name,category,location_id,location_name,produced,sold,written_off,on_hand,reserved,available,price_kzt,cost_kzt,weight_grams}]`. Totals produced/sold/written_off reflect selected inclusive dates; on_hand/reserved/available always live stock (explicit labels).
- GET `/records?kind=production|sales|waste&location_id&start_date&end_date&page=1&page_size=100`: `{items:[{id,kind,product_id,product_name,location_id,location_name,date,quantity,reason?,unit_price_kzt?,created_at}],total,page,page_size}`. POST `/records` `{kind,product_id,location_id,date,quantity,reason?,unit_price_kzt?}`. PATCH `/records/{kind}/{id}` same optional mutable `quantity,date,reason,unit_price_kzt`; updates validate live inventory/reservations and never silently clamp.
- POST `/forecasts`: `{product_id,location_id,target_date,horizon_days?:1}` → `{id,product_id,product_name,location_id,target_date,horizon_days,predicted_demand,recommended_production,existing_inventory,expected_surplus,stockout_risk,method,explanation,generated_at,mae:number|null,evaluation_points,history:[{date,sales,production}],daily:[{date,predicted_demand,recommended_production}],demo_data}`. Forecast target must follow today/history; forecast excludes date >= target. Horizon 1–14. GET `/forecasts` array of saved summaries; GET `/history?product_id&location_id` → `[{date,sales,production,waste}]`.
- GET `/dashboard?location_id&start_date&end_date`: `{demo_data,period:{start_date,end_date},metrics:{produced,sold,unsold,written_off,waste_kg,loss_kzt,forecast_demand,potential_savings_kzt,active_listings},trends:[{date,sales,production,waste,forecast}],best_sellers:[{name,quantity}],surplus_products:[{name,quantity}],recommendations:[string],savings_methodology:string}`. Unsold stock, surplus products and active listings are explicitly current; production/sales/waste/losses are date-filtered. `forecast_demand` predicts the day after selected end_date. Trend `forecast` is chronological prediction using only earlier days, null if insufficient data. `potential_savings_kzt` is explicitly an illustrative recoverable-cost scenario from recorded writeoffs at 20%, not achieved savings.
- GET `/listings?location_id&search&status=active|inactive|all`: `[{id,product_id,product_name,category,location_id,location_name,address,quantity,available_quantity,reserved_quantity,original_price_kzt,discounted_price_kzt,pickup_start,pickup_deadline,status,description,weight_grams}]`. POST `{product_id,location_id,quantity,discounted_price_kzt,pickup_start,pickup_deadline,description?}`. PATCH `/listings/{id}` `{quantity?,discounted_price_kzt?,pickup_start?,pickup_deadline?,status?:"active"|"inactive",description?}`; allocated quantity cannot exceed unallocated eligible inventory. Units allocated to listing are reserved from normal sales; order reservation uses listing availability. Deadline checked server-side.
- GET `/orders` → `[{id,status:"reserved"|"collected"|"cancelled",customer_name,total_kzt,created_at,items:[{id,listing_id,product_name,quantity,unit_price_kzt,pickup_deadline,location_name}]}]`; POST `{customer_name,items:[{listing_id,quantity}]}` → order; POST `/orders/{id}/cancel` and `/orders/{id}/collect` → updated order. Cancelling before deadline releases order stock back to listing. Collection subtracts inventory and records sales once; only collection counts impact. Demo checkout only.
- GET `/impact?location_id&start_date&end_date`: `{demo_data,recovered_units,recovered_weight_kg,recovered_value_kzt,written_off_units,written_off_kg,baseline:{start_date,end_date,waste_kg,observed_days,required_days,complete},comparison_complete:boolean,change_percent:number|null,trends:[{date,waste_kg,recovered_kg}],methodology:[string],potential_avoided_waste_kg:null}`. Baseline is preceding equal-length period. Percentage is suppressed unless both periods have production coverage for every day and baseline waste is nonzero; no causality/CO2 claims. Weight derives from catalog grams snapshotted when placing the order; it is not a physical weighing. Default 42-day synthetic history does not support a full preceding 30-day baseline; a 14-day period does.
- POST `/import` multipart `file` CSV, maximum 2 MB / 5000 rows, required headers `kind,product_id,location_id,date,quantity`; optional `reason,unit_price_kzt`; all-or-nothing validation → `{imported:number,message}`; invalid → 422 `{detail,errors:[{row,message}]}`. Inventory reconciliation enforced in row order. UTF-8 comma-separated, ISO dates. GET `/export` same CSV columns and all records; optional date/location filters.
- POST `/demo/reset` `{confirm:"RESET SAQTA DEMO"}` → `{message,products,days,workspace_mode}`. Refuses in real mode. Reset erases only configured database; protected UI confirmation required.
- POST `/economics` `{subscription_kzt:30000,hosting_kzt:3000,computation_kzt:2000,support_kzt:3000,misc_kzt:1000,cac_kzt:40000,lifetime_months:12,revenue_target_kzt:300000,locations:10}` → `{revenue_kzt,variable_costs_kzt,contribution_kzt,contribution_percent,ltv_kzt,ltv_cac,cac_payback_months,customers_for_target,arr_kzt}`. Zero denominators return null.

Run `python -m app.seed` after `alembic upgrade head` to initialize an isolated demo. The synthetic seed uses reproducible PRNG `24042` and anchor `DEMO_ANCHOR_DATE` (default current Astana date); 42 days × 5 products × 2 locations. Current pickup windows use execution time. `python -m app.seed --reset` explicitly resets a demo. A separate real-mode database requires `python -m app.seed --empty` after migration, creating only its bakery, placeholder location and settings. History does not roll forward automatically; ordinary API actions and expired-listing cleanup can update operational records.
